## 1. 产品概述

### 1.1 产品背景

在研发中的产品遇到了用户 P2P 连接延迟过高的问题。为了定位问题根因，需要一个独立的基准测试工具，排除业务层干扰，直接测量 P2P 连接的实际网络状况。P2PTest 正是为此而设计的轻量级测试工具。

### 1.2 产品定位

- **类型**：P2P 网络质量基准测试工具
- **核心价值**：提供纯净的 P2P 连接环境，测量真实的网络延迟、丢包率等指标，作为产品优化的参考基准
- **形态**：移动端 App（Flutter/Dart 跨平台），无需后端服务器，完全去中心化

### 1.3 目标用户

| 用户角色 | 使用场景 |
|---------|---------|
| 开发工程师 | 排查 P2P 延迟问题，获取基准测试数据 |
| 测试工程师 | 在不同网络环境下测试 P2P 连通性和性能 |
| 网络工程师 | 诊断 NAT 穿透成功率和网络质量 |
| 产品经理 | 评估 P2P 方案的可行性和用户体验 |

### 1.4 核心功能概览

1. **地址获取与展示**：通过 STUN 服务获取自身公网 IP 和端口，同时获取内网 IP 和端口，均展示在界面顶部并支持一键复制，公网地址自动查询展示 IP 归属地
2. **STUN 服务配置**：默认 STUN 不可用时，支持用户手动配置 STUN 服务器，提供默认可选列表，配置自动持久化
3. **监听用户管理**：手动添加/删除监听用户，输入对方 IP 和端口建立 P2P 连接
4. **实时监控**：每秒依次探测用户连接状态，实时展示延迟（RTT）、丢包率
5. **IP 归属地展示**：自动查询并展示监听用户的 IP 归属地信息（省市/运营商）
6. **自动重连**：断线后的梯度重连机制，重连失败后降级为每分钟探测
7. **一键清除**：一键清除所有已断开连接的监听用户

### 2.2 用户操作流程

1. 打开 App，界面显示加载动画（转圈）和提示文字「正在获取公网地址…」
2. STUN 服务自动获取自身公网 IP 和端口，同时获取内网 IP 和端口
   - **成功**：界面顶部展示自身公网地址（IP:Port）及 IP 归属地（省市/运营商），同时展示内网地址（IP:Port），均支持一键复制，进入主界面
   - **失败**：自动切换到 STUN 服务器配置界面，提供默认可选列表供用户选择或手动输入 STUN 服务器地址，选择后重新获取
3. 用户选择的 STUN 服务器地址会被记录，下次启动自动优先使用
4. 点击「添加用户」按钮，系统自动检测剪切板内容
   - 剪切板含合法 `IP:Port` → 弹窗提示是否自动填入
5. 在弹出的对话框中输入（或自动填入）对方的公网 IP 和端口
   - 对话框提供「自动填入」按钮（仅剪切板内容合法时显示）
6. 确认后，App 发起 P2P 打洞连接
7. 连接结果实时展示在监听用户列表中
8. 对已添加的用户，可左滑呼出删除按钮进行删除

### 2.3 操作总结

| 操作 | 触发方式 | 结果 |
|-----|---------|------|
| 获取地址 | App 启动自动执行 | 转圈等待 → 成功展示公网 IP:Port + 归属地 + 内网 IP:Port / 失败转入配置 |
| 配置 STUN 服务器 | 获取失败自动弹出，或主动进入设置 | 选择/输入 STUN 地址，记录并重试 |
| 添加监听用户 | 点击「+」按钮 | 检测剪切板 → 提示自动填入 → 弹出 IP/端口输入对话框 |
| 删除监听用户 | 列表项左滑 | 呼出删除按钮，确认删除 |
| 查看连接状态 | 自动展示 | 列表实时更新连接状态和网络指标 |
| 清除断开连接 | 点击「清除断开」按钮 | 一键移除所有已断开的监听用户 |

## 3. 功能模块

### 3.1 地址获取与展示

- App 启动后，显示加载动画（转圈）和提示文字「正在获取公网地址…」
- 优先使用用户上次选择的 STUN 服务器（如有记录），否则使用默认列表
- 依次尝试 STUN 服务器直到成功
- 获取成功后，界面顶部同时展示公网地址和内网地址：
  - **公网地址**：STUN 获取的公网 `IP:Port`，支持点击复制到剪贴板
  - **内网地址**：本机内网 `IP:Port`（UDP 监听端口），支持点击复制到剪贴板
- 公网地址下方自动查询并展示本机公网 IP 归属地（省市/运营商）
  - 查询中显示「查询中...」
  - 查询失败显示「未知」
- 如所有 STUN 服务器均获取失败，自动转换为 STUN 服务器配置界面

### 3.2 STUN 服务器配置

- 当默认 STUN 服务不可用时，自动弹出配置界面
- 用户也可在主界面主动进入 STUN 配置（点击公网地址卡片上的设置图标）
- 配置界面提供一个**默认可选的 STUN 服务器列表**，用户可点选：
  - `61.151.231.231:2311`（初始默认）
  - `61.151.231.231:2312`
  - `stun.l.google.com:19302`
  - `stun1.l.google.com:19302`
  - `stun2.l.google.com:19302`
  - `stun.cloudflare.com:3478`
  - `stun.nextcloud.com:443`
  - `stun.stunprotocol.org:3478`
  - `stun.ekiga.net:3478`
  - `stun.ideasip.com:3478`
  - `stun.schlund.de:3478`
- 同时支持用户**手动输入**自定义 STUN 服务器地址（格式：`host:port`）
- 用户选择或输入后，系统记录该 STUN 服务器地址到本地存储
- 下次启动 App 时，自动优先使用用户记录的 STUN 服务器
- 选择后立即使用新的 STUN 服务器重新获取公网地址

### 3.3 监听用户管理

#### 3.3.1 添加用户

- 点击「添加用户」按钮时，系统自动读取剪切板内容
- 如果剪切板内容为合法的 `IP:Port` 格式，弹窗提示用户是否自动填入
  - 用户选择「是」：IP 和端口自动填入输入框
  - 用户选择「否」：打开空白输入框
- 如果剪切板内容不合法，直接打开空白输入框
- 输入对话框中提供「自动填入」按钮（仅当剪切板内容为合法 IP:Port 时显示）
- 输入字段：
  - IP 地址（必填，合法 IPv4 地址）
  - 端口号（必填，1-65535）
- 确认后将用户添加到监听列表，并自动发起 P2P 打洞

#### 3.3.2 监听用户列表

- 展示所有已添加的监听用户
- 系统每秒依次探测一个用户（轮询），更新其连接状态和网络指标
- 每个用户项展示：
  - IP:Port 地址
  - IP 归属地（省市/运营商）
  - 连接状态（已连接 / 连接中 / 重连中 / 已断开 / 降级监控中）
  - 延迟（RTT，ms）
  - 丢包率（%）
- 列表实时更新

#### 3.3.3 删除用户

- 列表项支持左滑操作
- 左滑呼出删除按钮
- 点击删除后，关闭与该用户的 P2P 连接，从列表中移除

#### 3.3.4 一键清除断开连接

- 在「监听用户」标题栏提供「清除断开」按钮（图标或文字）
- 点击后一次性移除所有状态为「已断开」的监听用户
- 清除前弹出确认对话框，防止误操作
- 清除后关闭对应的 P2P 连接资源，更新本地持久化数据

### 3.4 P2P 连接

#### 3.4.1 连接方式

- 所有用户地位平等，无主控/连接端之分
- 每个用户通过 STUN 获取公网地址后，手动添加对方地址建立连接
- 使用 UDP 打洞建立点对点直连，支持双向通信

#### 3.4.2 NAT 穿透

- 使用 STUN 服务器获取公网地址
- 基于 UDP 打洞实现 NAT 穿透，仅支持直连，**不使用 TURN 中继**
- 打洞失败则标记该用户为「连接失败」状态

#### 3.4.3 连接监控

实时展示每个监听用户的连接信息：

**探测机制**：系统每秒依次探测下一个监听用户（轮询），对其发送 Ping 并更新连接状态。N 个用户时，每个用户的有效探测间隔为 N 秒。

| 监控指标 | 说明 | 更新频率 |
|---------|------|---------|
| 连接状态 | 已连接 / 连接中 / 重连中 / 已断开 / 降级监控中 | 每次轮询到时更新 |
| 延迟（RTT） | 往返时延，单位 ms | 每次轮询到时更新 |
| 丢包率 | 最近 N 个包的丢失比例，单位 % | 每 5 秒更新 |

## 5. 技术选型

| 领域 | 技术方案 | 说明 |
|-----|---------|------|
| 客户端 | Flutter (Dart) | 跨平台移动端（iOS & Android） |
| P2P 通信 | UDP 直连 | 基于 Dart `RawDatagramSocket` 实现 UDP 打洞和通信 |
| NAT 穿透 | STUN 服务 | 使用 STUN 服务器获取公网地址，UDP 打洞穿透 NAT |
| IP 归属地 | IP 查询 API | 通过在线 API 查询 IP 归属地信息 |
| 数据持久化 | 本地存储 | 监听用户列表、STUN 服务器配置持久化到本地 |

## 7. 边界情况与异常处理

### 7.1 STUN 获取地址失败

- 优先使用用户上次记录的 STUN 服务器（如有），否则使用默认列表
- 依次尝试多个 STUN 服务器
- 获取过程中，界面显示转圈动画 + 「正在获取公网地址…」提示文字
- 所有 STUN 服务器均失败时，**自动切换到 STUN 服务器配置界面**
- 配置界面提供默认可选的 STUN 服务器列表，支持手动输入自定义地址
- 用户选择后点击「重新获取」，使用新的 STUN 服务器重试
- 用户选择的 STUN 服务器地址自动持久化，下次启动优先使用

### 7.2 断线重连机制

#### 重连策略

检测到 P2P 连接断开后，自动按梯度策略重连：

| 重连次数 | 等待时间 | 累计等待 |
|---------|---------|---------|
| 第 1 次 | 1 秒 | 1 秒 |
| 第 2 次 | 5 秒 | 6 秒 |
| 第 3 次 | 10 秒 | 16 秒 |
| 第 4 次 | 30 秒 | 46 秒 |
| 第 5 次 | 60 秒 | 1 分 46 秒 |

共 5 次重连尝试，最长等待约 1 分 46 秒。

#### 重连结果

- **重连成功**：恢复「已连接」状态，恢复正常轮询探测
- **重连失败（5 次用尽）**：标记该用户状态为「已断开」，降级为每 1 分钟探测一次。若降级探测恢复连接，则自动切回正常轮询；用户也可通过「清除断开」一键移除所有断开的用户

### 7.3 P2P 打洞失败

- 添加用户后发起 P2P 打洞，超时限制 10 秒
- 打洞失败（包括对称型 NAT 等无法穿透的情况）：
  - **不使用中继**，直接标记为「连接失败」
  - 用户可删除后重新添加尝试

### 7.4 网络切换

- 用户切换网络（如 Wi-Fi ↔ 移动数据）会导致 IP 变化
- 自动重新获取 STUN 公网地址并更新顶部展示
- 已有连接视为断线，触发重连流程

### 7.5 重复添加

- 添加已存在的 IP:Port 时，提示「该用户已在监听列表中」，不重复添加

## 9. 风险评估

| 风险 | 影响 | 等级 | 应对策略 |
|-----|------|-----|---------|
| 对称型 NAT 下打洞失败率高 | 部分用户无法连接 | 高 | 明确告知用户，不使用中继是设计决策（测试纯 P2P 性能） |
| STUN 服务器不稳定 | 公网地址获取失败 | 中 | 配置多个 STUN 服务器作为备选；获取失败时自动弹出 STUN 配置界面，支持用户手动选择/输入服务器地址并持久化 |
| IP 归属地查询 API 不可用 | 无法展示归属地信息 | 低 | 查询失败时优雅降级，展示「未知」；缓存已查询结果减少请求 |
| 移动端后台运行限制 | App 切到后台后连接中断 | 中 | 使用前台服务保活，提示用户保持前台运行 |
| 用户手动输入地址易出错 | 连接建立失败 | 低 | 提供输入格式校验和友好错误提示；支持从剪切板自动识别并填入 IP:Port |
