## 1. 产品概述

### 1.1 产品背景

P2PTest 是一个点对点（Peer-to-Peer）网络通信测试工具，旨在为开发者提供便捷的 P2P 连接测试、性能评估和问题诊断能力。随着去中心化应用（dApp）、实时通信（RTC）和分布式系统的快速发展，对 P2P 网络层的测试需求日益增长。

### 1.2 产品定位

- **类型**：开发者工具 / 测试框架
- **核心价值**：简化 P2P 网络连接测试流程，提供可视化的测试结果与诊断信息
- **开源协议**：MIT License

### 1.3 目标用户

| 用户角色 | 使用场景 |
|---------|---------|
| 后端开发者 | 验证 P2P 通信模块的连通性和稳定性 |
| 网络工程师 | 诊断 NAT 穿透、网络延迟等问题 |
| QA 工程师 | 对 P2P 功能进行自动化测试 |
| 开源贡献者 | 基于框架扩展自定义测试场景 |

## 2. 功能需求

### 2.1 P2P 连接管理

- **建立连接**：支持在两个节点之间建立直接的 P2P 连接
- **连接状态监控**：实时显示连接状态（连接中 / 已连接 / 断开 / 错误）
- **连接参数配置**：支持自定义超时时间、重试次数、心跳间隔等参数
- **多连接管理**：支持同时管理多个 P2P 连接

### 2.2 数据传输

- **消息发送与接收**：支持在已连接的节点间收发文本和二进制数据
- **大文件传输**：支持分片传输大文件，显示传输进度
- **传输速率统计**：实时统计上传/下载速率、总传输量
- **数据完整性校验**：通过校验和确保数据传输的完整性

### 2.3 NAT 穿透

- **STUN 支持**：集成 STUN 协议，获取节点的公网地址
- **TURN 支持**：在直连失败时，通过 TURN 中继进行通信
- **NAT 类型检测**：自动检测并报告当前网络的 NAT 类型
- **穿透成功率统计**：记录不同 NAT 类型组合下的穿透成功率

### 2.4 节点发现

- **信令服务器**：提供轻量级信令服务器，用于节点间的初始握手
- **局域网发现**：支持通过 mDNS/广播在局域网内自动发现节点
- **手动连接**：支持通过节点 ID 或地址手动建立连接

### 2.5 测试与诊断

- **延迟测试**：测量节点间的 RTT（往返时延）
- **带宽测试**：评估 P2P 连接的可用带宽
- **丢包率测试**：统计数据传输过程中的丢包情况
- **连接日志**：详细记录连接建立和数据传输过程中的事件
- **测试报告生成**：自动生成包含各项指标的测试报告

## 3. 非功能需求

### 3.1 性能要求

| 指标 | 目标值 |
|-----|-------|
| 连接建立时间 | ≤ 3 秒（同一局域网），≤ 10 秒（跨 NAT） |
| 消息延迟 | ≤ 50ms（局域网），取决于网络环境（广域网） |
| 最大并发连接数 | ≥ 100 |
| 大文件传输 | 支持 ≥ 1GB |

### 3.2 安全性要求

- 所有 P2P 通信支持端到端加密（E2EE）
- 节点身份认证机制，防止中间人攻击
- 敏感配置信息加密存储

### 3.3 可用性要求

- 提供 CLI 和 API 两种使用方式
- 清晰的错误提示和排障指引
- 完善的使用文档和示例代码

### 3.4 兼容性要求

- **操作系统**：macOS、Linux、Windows
- **网络环境**：IPv4 / IPv6、各类 NAT 类型

## 4. 系统架构

### 4.1 整体架构

```
┌─────────────────────────────────────────────┐
│                  CLI / API                   │
├─────────────────────────────────────────────┤
│              测试引擎（Test Engine）           │
├──────────┬──────────┬───────────┬───────────┤
│ 连接管理  │ 数据传输  │ NAT 穿透   │ 节点发现   │
├──────────┴──────────┴───────────┴───────────┤
│            P2P 传输层（Transport）             │
├─────────────────────────────────────────────┤
│          网络层（UDP / TCP / QUIC）            │
└─────────────────────────────────────────────┘
```

### 4.2 模块划分

| 模块 | 职责 | 说明 |
|-----|------|-----|
| `core` | P2P 核心协议实现 | 连接建立、数据传输、心跳维护 |
| `nat` | NAT 穿透 | STUN/TURN 客户端、NAT 类型检测 |
| `discovery` | 节点发现 | 信令服务器、局域网发现 |
| `test` | 测试引擎 | 延迟/带宽/丢包率测试、报告生成 |
| `cli` | 命令行接口 | 用户交互、参数解析、结果展示 |
| `api` | 编程接口 | 供外部程序集成调用 |

## 5. 接口设计

### 5.1 对外接口

#### CLI 命令示例

```bash
# 启动节点
p2ptest start --port 8080

# 连接到远程节点
p2ptest connect <peer-id>

# 运行延迟测试
p2ptest test latency --peer <peer-id> --count 100

# 运行带宽测试
p2ptest test bandwidth --peer <peer-id> --duration 30s

# 生成测试报告
p2ptest report --format json --output report.json
```

#### API 接口示例

```
POST   /api/v1/node/start          启动节点
POST   /api/v1/connect              建立连接
DELETE /api/v1/connect/:peer-id     断开连接
GET    /api/v1/peers                获取已连接节点列表
POST   /api/v1/test/latency         运行延迟测试
POST   /api/v1/test/bandwidth       运行带宽测试
GET    /api/v1/report/:test-id      获取测试报告
```

## 6. 数据模型

## 8. 风险评估

| 风险 | 影响 | 等级 | 应对策略 |
|-----|------|-----|---------|
| NAT 穿透在对称型 NAT 下失败率高 | 部分场景无法直连 | 高 | TURN 中继作为兜底方案 |
| 跨平台兼容性问题 | 部分系统功能受限 | 中 | 持续集成覆盖主流平台测试 |
| P2P 连接不稳定 | 测试结果波动大 | 中 | 增加重试机制和统计采样数量 |
| 安全漏洞 | 数据泄露风险 | 高 | 端到端加密 + 安全审计 |
